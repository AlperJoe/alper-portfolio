I programmed Pedro.

It's an online multiplayer card game, built with a low-level engine.

I wrote the game without a coding agent. That came to around 18,000 lines of Lua code.

or Pick a card.

How I built it

I worked with a designer on Pedro and wrote the game code myself. I used ChatGPT to talk through problems as I worked. I made the implementation decisions and put the game together one system at a time. From the start I split the code into three layers, the game on the phone, the server and a core that holds the rules, so each part could grow without breaking the others. Git kept a record of every change.

Take a single turn. You tap a card on your phone. The game has to work out which card you touched, check whether you can play it, and show everyone at the table what happened. I used LÖVE to draw the game and handle input. I wrote the rules in a separate Lua module so the game on your phone and the multiplayer server could use the same code to decide whether a move was legal.

That separation helped when something went wrong. If two players saw different things after a move, I could check what the server had accepted, what it had sent to each phone, and what each phone had drawn. Keeping the rule checks on the server cut down the moments when phones fell out of sync.

Getting Pedro onto real phones took its own work. I tested it, prepared the builds for release and kept fixing problems after the first builds went out. By the time Pedro shipped, that one turn connected code I'd written all the way from a tap on the screen to the game running on someone else's device.

Not in this mock: the opening card sheets, the embers and the menu. They stay as they are on the live site.
